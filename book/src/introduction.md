# Introduction

Keyhammer is a typo-tolerant search engine for short strings (words, names,
identifiers). Given a dictionary of weighted terms and a possibly misspelled
query, it returns the top-k terms of lowest edit cost. Edit costs are
keyboard-aware: swapping a key for a neighbouring one on a QWERTY layout, or
repeating a letter, costs less than an arbitrary substitution.

The core crate, `keyhammer`, is `no_std` (it needs `alloc`), forbids `unsafe`
and has no runtime dependencies.

## Status

Keyhammer is an **unpublished M0 prototype**. Please read the
[results](results.md) before relying on it:

- The search is exact: it returns the same top-k as a brute-force oracle, and
  the test suite checks this.
- On the M0 benchmark it was much faster than the previous engine in this
  repository, but its ranking quality (MRR) was **below a simple baseline** at
  every dictionary size tested.
- The cost table is provisional and has not been calibrated.
- The project claims no novelty: every ingredient is published work (see
  [prior art](prior-art.md)).
- Queries and terms are raw bytes, already lowercased. There is no Unicode
  handling.

## Quick example

```rust
use keyhammer::cost::CostModel;
use keyhammer::search::{SearchConfig, Searcher};
use keyhammer::trie::Trie;

// Terms come with a weight (higher ranks first among equal costs).
let trie = Trie::build(&[("hello", 100), ("help", 50), ("world", 10)]).unwrap();
let costs = CostModel::qwerty();
let mut searcher = Searcher::new();

// Costs are fixed point: 16 is one ordinary edit, so a budget of 32 allows
// about two edits.
let cfg = SearchConfig { k: 3, budget: 32, ..SearchConfig::default() };
let out = searcher.search(&trie, &costs, b"helo", &cfg).unwrap();
for hit in &out.hits {
    println!("{} (cost {}, weight {})", trie.term(hit.id), hit.cost, hit.weight);
}
```

Set `tsb: true` in `SearchConfig` to enable the subtree-signature bound; it
prunes work without changing the results (see [How it works](how-it-works.md)).
